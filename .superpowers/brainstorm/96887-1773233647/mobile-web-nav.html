El problema actual: en móvil web se usa el layout de app nativa. Las barras del navegador (URL bar, barra inferior) se superponen con el BottomNav y el contenido. ¿Qué enfoque tomamos?

PROBLEMAS ACTUALES
  • BottomNav tapado por la barra del navegador
  • AppBar + URL bar = doble barra arriba
  • Safe areas no gestionadas para browser chrome
  • RpgHud completo ocupa demasiado espacio vertical
OBJETIVO

Que en móvil web se vea y use correctamente, sin que las barras del navegador rompan el layout.

¿Qué enfoque de navegación usamos para móvil web?

A

Fix BottomNav + Safe Areas

Mantener el BottomNav pero añadir padding dinámico para las barras del navegador (usando env(safe-area-inset-bottom) via MediaQuery). AppBar se mantiene. Cambio mínimo — solo corregir superposiciones.

Pro

  • Mínimos cambios de código
  • Experiencia familiar (app nativa)

Con

  • Sigue viéndose como app, no web
  • Doble barra arriba (URL + AppBar)
B

Nuevo layout "Mobile Web" (sin AppBar)

Para 360–900px en web: eliminar AppBar, RpgHud compacto en top strip, BottomNav con padding-bottom dinámico. Un tercer breakpoint: móvil nativo / móvil web / desktop web.

Pro

  • Experiencia optimizada para browser
  • Más espacio para contenido

Con

  • Lógica extra en cada screen
  • 3 layouts en vez de 2
C

Sidebar colapsado (hamburger) en móvil web

En móvil web usar la sidebar de desktop pero colapsada por defecto (icono hamburger en top). Al pulsar se abre como un drawer. Sin BottomNav en web — ni en desktop ni en móvil.

Pro

  • Un solo layout "web" para todos los anchos
  • Más consistente visualmente

Con

  • Mayor cambio en DashboardScreen
  • Hamburger menos intuitivo en móvil
